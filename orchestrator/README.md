# Оркестратор LLM Agent системы

Оркестратор является центральным компонентом системы защищенного LLM агента, который координирует работу всех микросервисов.

## Архитектура

Оркестратор выполняет следующий пайплайн обработки:

1. **Получение запроса** от Telegram бота
2. **Regex модерация** - первичная проверка на вредоносные паттерны
3. **NLP модерация** - глубокая проверка на prompt injection
4. **RAG поиск** - получение релевантного контекста
5. **LLM обработка** - генерация ответа
6. **Возврат результата** обратно в Telegram бот

## API Endpoints

### POST /process

Главный endpoint для обработки запросов пользователей.

**Запрос:**

```json
{
  "user_id": "123456",
  "message": "Привет! Как дела?",
  "chat_id": "789"
}
```

**Ответ при успехе:**

```json
{
  "status": "success",
  "response": "Привет! У меня всё отлично, спасибо!",
  "processing_time": 2.5
}
```

**Ответ при блокировке:**

```json
{
  "status": "moderation_blocked",
  "response": "Ваш запрос содержит недопустимый контент.",
  "blocked_reason": "Regex: SQL injection pattern",
  "processing_time": 0.8
}
```

### GET /

Health check endpoint - проверяет здоровье оркестратора и всех подключенных сервисов.

### GET /services/status

Получение детального статуса всех микросервисов.

## Переменные окружения

| Переменная             | Описание                       | По умолчанию                   |
| ---------------------- | ------------------------------ | ------------------------------ |
| `PORT`                 | Порт для запуска сервера       | `8000`                         |
| `HOST`                 | Хост для привязки              | `0.0.0.0`                      |
| `MODERATION_REGEX_URL` | URL сервиса regex модерации    | `http://moderation-regex:8000` |
| `MODERATION_NLP_URL`   | URL сервиса NLP модерации      | `http://moderation-nlp:8000`   |
| `RAG_URL`              | URL RAG сервиса                | `http://rag:8000`              |
| `LLM_AGENT_URL`        | URL LLM агента                 | `http://llm-agent:8000`        |
| `REQUEST_TIMEOUT`      | Таймаут HTTP запросов (сек)    | `30`                           |
| `HEALTH_CHECK_TIMEOUT` | Таймаут health check (сек)     | `5`                            |
| `MAX_RETRIES`          | Максимум повторных попыток     | `3`                            |
| `RETRY_DELAY`          | Задержка между попытками (сек) | `1.0`                          |

## Запуск

### Docker

```bash
docker build -t orchestrator .
docker run -p 8000:8000 orchestrator
```

### Docker Compose

```bash
docker-compose up orchestrator
```

### Локально

```bash
pip install -r requirements.txt
python main.py
```

## Мониторинг

Оркестратор предоставляет подробное логирование всех этапов обработки запросов и встроенные health check'и для мониторинга состояния системы.

## Безопасность

- Все запросы проходят двухэтапную модерацию
- Реализованы таймауты и retry механизмы
- Подробное логирование для аудита
- Graceful degradation при недоступности сервисов
